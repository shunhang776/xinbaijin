# 白槿 v2 全系统重构方案（终版 v5）

## Context

当前 68 文件，核心问题：无层级边界、插件空壳、配置分散、main.py 1400+行、LLM 调用分散、跨层逆向引用、模块错层、加功能改核心、排障靠猜。

目标：7 层架构，加功能=加文件+注册，排障=trace_id+健康检查，灰度=特性开关+双轨。

---

## 一、架构总览

```
7 层 + 4 扩展机制 + 5 横切能力
```

**7 层（自下而上）：**

```
L0 core/           Foundation     类型/配置/异常/缓存/指标/日志/构造注入
L1 infra/          Infrastructure LLM(熔断) DB 嵌入
L2 memory/         Memory Engine  可插拔索引 检索 写入(异步) 演化(含压缩)
L3 personality/    Personality    状态 感官 欲望 直觉 生活流 独白
L4 services/       Services       纯技术服务(联网/安全/视觉)
L5 domain/         Domain         标准接口领域模块
L6 plugins/prompt  Presentation   plugins=编排,prompt=Jinja2纯渲染
L7 app/ops/        Application    FastAPI/CLI/守护/健康/认证
```

**4 扩展机制：**

| 机制 | 核心 | 新功能成本 |
|------|------|-----------|
| 插件注册表 | `@register` + pydantic 校验 + 中间件 + 重名检测 + **依赖拓扑排序** | 加文件+装饰器 |
| 可插拔索引 | `BaseIndex` + `INDEX_REGISTRY` + `FusionStrategy` | 加文件+实现接口+注册 |
| 领域模块 | `DomainModule` + 显式注册 | 加文件+实现接口+注册 |
| 特性开关 | `FeaturesConfig` 功能级，热生效，按比例灰度 | 改配置 |

**5 横切能力：**

| 能力 | 载体 |
|------|------|
| 全链路追踪 | `contextvars` trace_id+span+session_id，关键节点自动子span，cross-thread/coroutine 自动传递 |
| 健康检查 | liveness/readiness 双检查 + 0-100 健康分 + degraded 分级(轻度/重度)，10s TTL |
| 分层异常+错误码 | `BaijinBaseError` + INF/MEM/PLG 前缀编码，context 自动注入 trace/span，禁止裸抛 |
| 结构化日志+指标 | JSON 格式，contextvars 自动送 trace/span/耗时；慢调用自动 warning 埋点；动态日志级别(按 trace_id/user_id 临时开启，超时自恢复) |
| 分层缓存 | TTL+LRU+三防：空值缓存(防穿透)、TTL 随机偏移(防雪崩)、热点预热(防击穿) |

**调用链：**
```
app(middleware生成trace_id) → 并发调plugins(Result[T]) → 组装PromptData → build_prompt(data,Jinja2) → infra.llm
```

**铁律五条：**
1. Layer N 只 import Layer < N 的 `__init__.py`。内部子包 `_` 前缀私有。**同包内部可互相导入 `_` 子包。**
2. `__init__.py` 仅导出 Protocol 接口，不导出具体实现类
3. 正常向下调用直接 import。**跨层逆向依赖用构造注入，仅在启动时注入一次，运行期禁止调用容器**
4. 所有跨层 DTO 统一定义在 `core/types.py`
5. 所有单例纳入 DI 容器管理（构造注入）

#### 关键类型

```python
# core/types.py

@dataclass
class Result(Generic[T]):
    ok: bool
    data: Optional[T] = None
    error_code: Optional[str] = None    # INF_LLM_TIMEOUT / MEM_GRADE_PROTECTED / PLG_PARAM_INVALID
    error_msg: str = ""

@dataclass
class PromptData:
    user_msg: str; identity: str; state_snapshot: dict
    senses_snapshot: dict; life_activity: str; idle_thought: str
    mood_hints: dict; intuition: str; memory_cloud: str
    recent_memories: list[dict]; emotion_timeline: str
    preferences: str; reminders: list[str]; recent_chat: list[dict]
    sender_type: str = "qq"
    extra: dict[str, Any] = {}        # 扩展字段，新领域能力先放这

@dataclass
class MemoryItem(TypedDict, total=False):
    id: str; content: str; grade: str; timestamp: int
    meta: dict; schema_version: int = 1

@dataclass
class HealthStatus:
    component: str
    status: Literal["ok", "degraded", "error"]
    latency_ms: float; error_code: str = ""; metrics: dict = {}

class LifecycleComponent(Protocol):
    def start(self) -> None: ...
    def stop(self, timeout: float = 5) -> None: ...  # 等队列排空，超时强制退出

class DomainModule(Protocol):
    name: str; priority: int = 0
    def get_context(self) -> str: ...
    def get_tools(self) -> list[dict]: ...

class BaseIndex(Protocol):
    name: str; weight: float = 1.0
    def add(self, item_id: str, data) -> None: ...
    def remove(self, item_id: str) -> None: ...
    def search(self, query, top_k: int) -> list[tuple[str, float]]: ...
    def rebuild(self, items: list) -> None: ...
    def health_check(self) -> HealthStatus: ...

class FusionStrategy(Protocol):
    def merge(self, results: dict[str, list], top_k: int) -> list[dict]: ...
```

| 层 | 策略 |
|----|------|
| L0-L2 | 抛对应层异常(code+context)，不静默 |
| L3-L5 | 捕获下层→转本层→补 context |
| L6 plugins | 捕获所有，debug 日志，返回 `Result(ok=False, error_code=..., ...)`，**绝不向上抛** |

#### 插件注册表（完整版）

```python
# plugins/registry.py
@dataclass
class PluginMeta:
    name: str; func: callable
    dependencies: list[str] = []    # 前置依赖
    conflicts: list[str] = []       # 互斥插件
    input_schema: Optional[type[BaseModel]] = None  # pydantic 校验

_plugin_registry: dict[str, PluginMeta] = {}

def register(name: str, **meta_kwargs):
    if name in _plugin_registry:
        raise PluginError(code="PLG_DUPLICATE_NAME", ...)  # 重名直接报错
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            # pydantic 入参校验 → 依赖检查 → contextvars trace_id+span → 执行+耗时 → 异常→Result
        _plugin_registry[name] = PluginMeta(name=name, func=wrapper, ...)
        return wrapper
    return decorator
```

#### 优雅启停约定

```python
class LifecycleComponent(Protocol):
    def start(self) -> None: ...
    def stop(self, timeout: float = 5) -> None: ...
```

写入队列：`stop()` → 先停接收 → 排空队列 → 退出，保证不丢记忆。
定时任务：`stop()` → 取消待执行 → 释放线程。
L7 lifespan 关闭时逆序调用 `stop()`：**先停上层任务 → 再停底层写入**。

### 6.2 DI 容器 = 构造注入 + 生命周期自动编排 + 懒加载

        """注册时自动检测是否实现 LifecycleComponent。lazy=True 首次调用才 init"""

## 十一、生产安全加固（上线前必做）

### 11.1 进程信号优雅处理

```python
# core/signal_handler.py — 全局信号管理
# 注册 SIGINT/SIGTERM/Ctrl+C → 触发全局优雅停止：
#   1. 停止接收新请求/新任务
#   2. 排空写入队列（最大等待 10s，超时强制退出）
#   3. 关闭 DB/索引/模型
#   4. 退出进程
# Windows 额外适配控制台关闭事件（无标准 POSIX 信号）
```

所有入口（`main.py`/`ops/daemon.py`）统一引入 `install_signal_handlers()`。

### 11.2 SQLite 生产级加固

```python
# infra/database/connection.py
PRAGMA journal_mode=WAL
PRAGMA synchronous=NORMAL       # 平衡性能+安全，不极端 FULL
PRAGMA busy_timeout=5000        # 多线程锁等待，不直接报错
PRAGMA wal_autocheckpoint=1000  # 控制 WAL 文件大小
# 定时任务：PRAGMA wal_checkpoint(TRUNCATE) 归档 WAL
# 连接池：限制最大 5 连接，防泄露
# 关键写入强制显式事务
```

### 11.3 敏感信息脱敏

- `.env` 文件权限：Windows 只读，代码禁止硬编码密钥

### 11.4 内存 OOM 防护

- 所有缓存强制硬上限（`core/cache.py`、`recent_chat.py`）
- 健康检查增加进程内存指标，超阈值标 `degraded`

### 11.5 路由集中管理 + 404 友好兜底

- 所有 API 路径收口 `core/constants.py` 常量，禁止硬写 URL
- `app/routes/__init__.py` 统一注册，不漏不重
- FastAPI 全局 404 handler 返回标准 `Result(ok=False, error_code="APP_NOT_FOUND")`
