# 白槿 v2 第一周治理系统建设执行计划

> 目标：用一周建立最小可信治理闭环，不继续扩展 Phase 1 业务代码。

---

## Day 1：目录、Git、任务模型

完成：

- 暂停 Phase 1；
- 建立 `白槿v2` 与 `白槿治理` 两个目录；
- 初始化本地 Git；
- 建立 baseline；
- 建立 `task.md`、`acceptance.yaml`、`risk.yaml`、`status.yaml` 模板；
- 建立任务状态机；
- 建立 `artifacts/current` 和 `history`。

验收：

- 能创建一个测试任务；
- 能生成 baseline tag；
- 能恢复到 baseline；
- Claude 无法随意修改治理目录。

---

## Day 2：确定性检查 MVP

安装和配置：

- Nox；
- Ruff；
- pytest；
- Import Linter。

完成：

- `nox -s lint architecture tests` 可运行；
- pytest 生成 JUnit XML；
- 创建 `good_case`；
- 创建 `syntax_error`、`circular_import`、`failing_test`。

验收：

- 好样例通过；
- 三个坏样例失败；
- 工具失败返回非零。

---

## Day 3：OPA/Conftest 政策门禁

完成：

- 安装 OPA/Conftest；
- 建立 `review-input.json` Schema；
- 编写最小 Rego 政策；
- 建立政策正反测试；
- 生成 `policy-result.json`；
- 生成 `final-report.md`。

验收：

- P0/P1、测试失败、报告缺失均被拒绝；
- OPA 解析失败时默认拒绝；
- 最终报告能被项目负责人看懂。

---

## Day 4：Codex 只读审查

完成：

- 编写 Codex 审查提示；
- 定义 `codex-review.schema.json`；
- 对一个小 diff 手动运行审查；
- 将 Codex 结果加入 OPA 输入；
- 验证 `safe_to_accept=false` 必须被拒绝。

验收：

- Codex 不修改候选代码；
- JSON 无效时拒绝；
- 两轮修复限制可执行。

---

## Day 5：安全与证据完整性

增加：

- mypy；
- Gitleaks；
- pip-audit；
- commit 匹配；
- 受保护测试清单；
- 测试数量下降报警；
- `missing_report`、`secret_leak`、`commit_mismatch` 投毒样例。

验收：

- 密钥泄漏被阻断；
- 旧报告不能复用；
- 受保护测试删除会失败。

---

## Day 6：Hook 与自动交接包

完成：

- Claude Stop Hook；
- 自动收集 Git 证据；
- 自动运行 Nox；
- 自动调用政策门禁；
- 自动生成 review package；
- 自动 block/allow；
- 自动修复最多两轮。

验收：

- Claude 不能在门禁失败时宣布完成；
- Hook 自身异常时阻断；
- 审查包内容完整。

---

## Day 7：低风险真实任务与回滚

选择三个低风险任务：

- 文档或注释修复；
- 一个纯函数；
- 一个不涉及数据库和公共接口的小 bug。

完成：

- 三个任务都走完整链路；
- 两次真实回滚演练；
- 汇总问题；
- 决定治理系统是否达到 `PROVISIONALLY_TRUSTED`。

不通过时继续修治理系统，不接管 Phase 1。

---

## 一周结束标准

```text
[ ] 好样例稳定通过
[ ] 所有投毒样例稳定失败
[ ] 工具异常默认拒绝
[ ] 报告绑定 commit
[ ] Codex 拒绝会被 OPA 拒绝
[ ] Claude 无法修改治理规则
[ ] 两次回滚成功
[ ] 三个低风险任务完成
[ ] 负责人可以理解最终报告
```

达到后，Phase 1 才能按小批次 R1、R2、R3 重新开始。
