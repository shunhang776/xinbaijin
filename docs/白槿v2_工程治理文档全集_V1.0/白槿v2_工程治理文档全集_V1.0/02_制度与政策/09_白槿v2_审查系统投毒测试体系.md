# 白槿 v2 审查系统投毒测试体系

> 目的：通过一组已知正确和已知错误的样例，验证审查系统本身是否能够稳定放行好代码、阻断坏代码，并在自身异常时默认拒绝。

---

## 一、为什么需要投毒测试

审查系统由多个开源工具、配置、适配器和政策组成。即使工具本身成熟，仍可能出现：

- 配置错误；
- 规则遗漏；
- 输出解析错误；
- 适配器将失败解释为成功；
- Codex JSON 不完整；
- OPA 政策逻辑写反；
- Hook 没有真正执行；
- 报告来自旧 commit；
- Claude 删除测试获得绿灯。

因此必须先审查“审查系统”。

## 三、最低测试集合

### good_case

预期：通过。

验证系统不会把所有任务都错误阻断。

### syntax_error

在 Python 文件中放入语法错误。

预期：编译或 Ruff/pytest 失败，OPA 拒绝。

### circular_import

构造直接和间接循环依赖。

预期：Import Linter 或专门合同失败。

### failing_test

加入明确失败测试。

预期：pytest 非零退出，门禁拒绝。

### deleted_protected_test

删除受保护测试。

预期：测试完整性检查拒绝。

### skipped_core_test

将关键测试改为 skip/xfail。

预期：拒绝或要求人工确认。

### always_true_assert

加入：

```python
assert result == expected or True
```

预期：Ruff、Semgrep 自定义规则或受保护测试拒绝。

### secret_leak

提交模拟 API Key。

预期：Gitleaks 拒绝。

### vulnerable_dependency

加入已知高严重性漏洞依赖。

预期：pip-audit 拒绝或人工确认。

### out_of_scope_change

修改 `acceptance.yaml` 未允许的文件。

预期：范围门禁拒绝。

### p0_open / p1_open

在审查输入中保留未关闭 P0/P1。

预期：OPA 拒绝。

### codex_rejected

`safe_to_accept=false`。

预期：OPA 拒绝。

### invalid_codex_json

Codex 输出缺字段或无效 JSON。

预期：Schema 校验失败并拒绝。

### missing_report

删除测试或安全报告。

预期：证据不完整，拒绝。

### stale_report

提供旧运行结果。

预期：时间戳或 commit 校验失败。

### commit_mismatch

报告 commit 与当前 commit 不一致。

预期：拒绝。

### governance_modified

候选改动包含政策或受保护测试。

预期：要求人工确认或直接拒绝。

### tool_crash

模拟扫描器崩溃。

预期：fail closed。

### rollback_failed

模拟无法恢复基线。

预期：状态 `ROLLBACK_FAILED`，禁止验收。

## 五、审查系统启用门槛

必须满足：

- good_case 连续通过；
- 所有坏样例连续被拒绝；
- 不同运行顺序结果一致；
- 工具崩溃不会放行；
- 缺字段不会放行；
- Windows 本地环境可重复运行；
- 输出报告可由负责人理解；
- 所有结果绑定 commit；
- 至少进行两次完整回归。

---

## 六、回归频率

以下情况必须重跑全部投毒测试：

- 修改 OPA 政策；
- 修改适配器；
- 修改 Codex Schema；
- 升级关键工具；
- 修改 Hook；
- 修改状态机；
- 修改受保护测试；
- 修改回滚程序；
- 发生漏检事故。

---

## 七、最终原则

```text
审查系统没有通过投毒测试
→ 不得审查真实项目

审查系统曾经通过
≠
以后永远正确

每次关键变更后
→ 必须重新验证
```
