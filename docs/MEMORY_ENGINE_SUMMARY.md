## 三、核心能力

### 3.1 检索：四路并行

```
query → classify_query() → 动态优先级
  ├─ 时间轴    bisect O(log n)     ≤ 1ms
  ├─ 关联索引   dict前缀匹配        ≤ 1ms
  ├─ 类别层    内存Markdown         ≤ 3ms
  └─ BM25+FAISS 混合检索           ≤ 25ms
                                    ─────
                   asyncio.gather   ≤ 25ms
```

**权重**：BM25 30% + 向量 70%（来自MemU论文最佳实践）
**距离转换**：FAISS距离 → 相似度 = (max - dist) / max

### 3.2 写入：异步零阻塞

```
用户消息 + 白槿回复
  │
  ├─ JSONL落盘（≤1ms，用户已收到回复）
  ├─ 入内存队列 + 原子快照
  │
  ▼ 单线程Worker
  ├─ 关键词提取 + 分类 + 分级
  ├─ SQLite写 + 时间轴 + BM25 + 关联索引
  ├─ FAISS向量编码 + 写入
  └─ 成功→更新快照 / 失败→重入队列（最多3次）
```

### 3.3 记忆保护

- **A/S级记忆永不自动删除**
- 所有删除为软删除（deleted=1）
- 每写操作自动事务化 + rollback

### 3.4 演化自治

| 频率 | 任务 |
|------|------|
| 每日03:00 | C级过期清理 |
| 每日03:00 | 数据库备份（保留7天） |
| 每日04:00 | 昨日对话摘要 |
| 每3天 | 热数据升级到类别层 |
| 每周日 | 全量去重+升级+降级+归档 |
| 每月1日 | FAISS全量重建+健康检查 |

### 3.5 崩溃恢复

- 写入队列全量快照（JSON格式）
- 原子写入（tmp+replace）
- 启动自动加载未完成任务
- 优雅停机清空快照

## 四、线程安全体系

| 组件 | 锁类型 | 保护范围 |
|------|--------|---------|
| 嵌入模型 | 检索锁 + 写入锁 | PyTorch编码串行化 |
| FAISS向量 | Lock | 读(add)+写(search)互斥 |
| BM25全文 | RLock | 增删改查 |
| 关联索引 | RLock | 双向映射读写 |
| 时间轴 | RLock | 排序数组操作 |
| SQLite | 线程本地连接 | 每线程独立连接 |
| 写入队列 | Queue | 单线程Worker消费 |
| 快照文件 | Lock | 磁盘IO互斥 |
| 引擎启停 | 幂等标记 | 防重复关闭 |

**全局锁顺序（杜绝死锁）**：
关联索引 → 时间轴 → BM25 → FAISS

**FAISS**：全局单线程（`omp_set_num_threads(1)`），禁止内部多线程

## 六、数据流向

```
写入（自底向上）：
  Resource → Item（分类/分级/关键词）→ 四个索引 → 类别层

检索（自顶向下）：
  类别层 → Item → Resource（按需）

演化（后台自治）：
  过期清理 → 摘要生成 → 去重合并 → 升级/降级 → 索引重建 → 备份
```

---

## 七、配置亮点

- 零硬编码：所有参数、路径、常量在 config.py
- 分层解耦：每层只调下一层，跨层调用不存在
- 渐进迭代：从Mem0单通道 → 双通道 → 四路并行逐步演进
- 降级方案：新引擎失败自动退回Mem0

---

## 八、已知约束

1. BGE-M3首次加载需~2秒（后续在内存中复用，CLI每次调用重建进程）
2. CLI模式每次调用启动+关闭引擎，适合低频交互场景
3. 旧Mem0仅1条记忆，数据量少
4. 写入Worker为单线程，超高并发写入场景需扩展
