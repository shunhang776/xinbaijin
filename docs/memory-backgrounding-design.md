# 记忆背景化（Memory Backgrounding）技术设计

> 不等用户问，记忆自动浸润每一次回复。

## 一、核心思路

**现在：** 用户问"我昨天干了什么" → FAISS 检索 → 贴进 prompt → 生成回答。记忆是字典，查到了才有用。

**改造后：** 每次对话，无论聊什么，自动检索与当前氛围相关的记忆 → 不贴原文，凝为"语义云" → 以低权重注入 prompt 头部 → 模型被轻微偏置。用户不觉得白槿在"回忆"，只觉得它"懂我"。

生物类比：海马体→皮层转移后的"残留痕迹"——不是显性回忆，是隐性启动。

## 二、激活值计算

每个记忆不再二值判断（检索到/未检索到），而是计算一个连续的激活强度 `a ∈ [0, 1]`：

```
a = s × t × e × f
```

| 维度 | 变量 | 计算 | 说明 |
|------|------|------|------|
| 语义相似度 | `s` | BGE-M3 cosine × 3 轮对话上下文 | 不只是刚发的一句话，加上前 3 轮对话做加权平均 |
| 时间衰减 | `t` | `exp(-λ × days_ago)`，λ=0.3 | 1天衰减74%，3天衰减41%，7天衰减12% |
| 情感权重 | `e` | 情绪标记强度 / 平均情绪强度 | 有强烈情绪的记忆加分（喜悦/愤怒/悲伤） |
| 关联频率 | `f` | `1 + 0.2 × log(1 + ref_count)` | 被多次关联过的记忆激活更强，对数压平 |

### 激活值分层呈现

```
a ≥ 0.8  → 直接融入（"昨晚那么晚睡，今天不困吗？"）
a 0.5-0.8 → 语气偏置（提到咖啡时偏向"苦""提神"）
a 0.2-0.5 → 选项偏好（多个选项时倾向相关方向）
a < 0.2  → 完全抑制，不产生任何影响
```

实际实现中，前三个层级通过语义云的**权重标签**体现（`#强#` / `#中#` / `#弱#`），而非硬编码逻辑。

## 三、语义云（替代"残留印象"句子）

### 格式

不写成完整句子。句子是显性指令，模型会当任务处理。

```
#记忆气息#
[凌晨3点, 疲惫, APK反编译, 遇到bug, 烦躁, 冰美式×2]  #强# 0.87
[ROG笔记本NPU检测, 16TOPS, 技术探索, 满意]          #中# 0.64
[冰美式不加糖, 咖啡, 苦, 偏好]                       #弱# 0.41
#气息结束#
```

### 生成逻辑

每个记忆条目 = `_summarize_to_labels(memory, activation)`。用 DeepSeek 从记忆文本中提取 3-6 个语义标签，只保留名词/形容词/情感词，扔掉语法结构。

### Prompt 位置

语义云放在 system prompt **最前面**，但在人格定义之后：

```
你是白槿...
[人格描述]

#记忆气息#
[...]
#气息结束#

用户：你好
```

权重控制：语义云的总 token 不超过 system prompt 的 15%，始终 ≤ 120 token。

## 四、相互抑制

### 规则

```
avg_a = 当前检索到的所有记忆的平均激活值
threshold = avg_a × 0.3

for each memory:
    if a < threshold:
        discard  // 弱信号噪音，直接丢
```

### 效果

聊工作时，电影相关记忆被自动抑制。聊感情时，技术话题记忆退到阈值以下。没有幽灵记忆。

## 五、触发策略

### 检索时机

- **每次 _process_message 都触发**，不是只在你问"我昨天干了什么"时才触发
- 检索 query = 当前用户消息 + 前 3 轮对话摘要（加权拼接，最近的最重）

### 检索半径

```
FAISS top-12（而非现在的 top-5）
→ 计算激活值 → 抑制过滤 → 取前 5 → 生成语义云
```

扩大初筛范围，用激活值和抑制机制做精筛。

### 冷启动保护

- 对话数 < 20 条时，语义云直接为空
- 对话数 20-50 条时，只用 top-3
- 对话数 > 50 条，完整启用

## 六、性能

| 操作 | 额外耗时 | 说明 |
|------|---------|------|
| FAISS 检索（top-12） | ~60ms | 当前 50ms，多 7 条 |
| 激活值计算 | ~5ms | 纯算术 |
| 语义云生成（LLM） | 0ms | 标签提取在记忆写入时预计算 |
| 相互抑制 | ~1ms | 纯算术 |
| **总计** | **~66ms** | 在现有 ~4s 链路上感知不到 |

语义云的标签提取在 `remember_sync` 写入记忆时顺带完成，不占查询链路。

## 七、文件改动

| 文件 | 改动 |
|------|------|
| `memory/background.py` | **新建**。激活值计算 + 语义云生成 + 相互抑制 |
| `memory/write.py` | 写入记忆时顺带预计算语义标签（存入 DB） |
| `prompt/builder.py` | `build_prompt` 注入 `#记忆气息#` 块 |
| `main.py` | `_build_messages` 调用 background 模块 |
| `data/memory.db` | items 表加 `labels` 字段（TEXT，逗号分隔标签） |

## 八、演进路线

1. **v1（本次）：** 语义云注入 prompt，基于激活值分层
2. **v2（未来）：** 语义云不贴 prompt，直接作为 soft prompt 加到嵌入层（需模型支持 token 注入）
3. **v3（远期）：** 长期运行后，高频激活的记忆标签微调嵌入矩阵——记忆从"查出来"变成"长进去"
