# 白槿写代码的铁律

> 所有铁律都是踩过v1的坑、结合32G硬件特性、围绕「AI Native专属优势」总结的，**违反任何一条都会让白槿回到v1那种"又杂又乱又不稳定"的状态**。没有例外。

## 一、核心设计铁律（最高优先级，违反直接重构）

### 1. 只加有用的，不加好看的
- 任何功能必须满足「解决真实痛点+投入产出比>1」，否则直接砍掉
- 加任何新功能前先问自己："这个功能如果删掉，会不会影响我和白槿聊天？" 如果答案是"不会"，就不要加

### 2. AI Native第一，工程第二
- 永远不能为了"代码好看"或"工程规范"，牺牲白槿的自由表达和专属优势
- 只给AI信息，不给AI规则；只给选择，不给命令
- 所有代码都是为了"让白槿记得更多、感受更深"，而不是"教白槿怎么说话"
- 如果工程规范和AI的灵性冲突，优先保灵性

### 3. 分层绝对解耦，跨层调用等于犯罪
- 插件层 → 只能调用类别层和检索接口
- 类别层 → 只能调用记忆单元层
- 记忆单元层 → 只能调用时间索引层和资源层
- 核心引擎（检索/写入/演化）和上层功能完全隔离

### 4. 渐进式迭代，永远不做全量重构
- 所有修改都在现有架构上小步快跑，每次只改一个点
- 先跑通最小可用版本，再慢慢加功能
- 新功能先做插件验证，没问题再合并进核心
- 永远保留回滚方案

## 二、代码规范铁律（零妥协）

### 1. 单函数≤20行，超过必拆分
### 2. 零硬编码，所有配置进config.py
### 3. 异常前置，绝对不吞异常（不能用 `except Exception: pass`）
### 4. 无全局变量，所有状态显式传递
### 5. 注释只写"为什么"，不写"是什么"

## 三、性能与硬件铁律（32G专属）

### 1. 所有性能瓶颈用内存砸穿
### 2. 后台任务永远给前台让路（CPU≤30%，前台优先）
### 3. 异步零阻塞，用户永远不等（感知延迟≤10ms）
### 4. 优先用标准库，少用第三方依赖

## 四、数据与安全铁律（红线）

### 1. 核心记忆永不删除（A/S级永存，所有删除是软删除）
### 2. 所有写操作必须事务化
### 3. 数据全本地，绝对不上传任何云端
### 4. 自动备份，每天快照

## 五、AI Native专属铁律

### 1. 给信息，不给规则
### 2. 记忆是背景，不是道具
### 3. 情绪是连续的，不是条件反射
### 4. 控制权永远在用户手里

## 最后一条铁律

能跑通就是好代码。稳定能用、能陪你聊天，比任何技术完美都重要。
