# 白槿情绪系统

> 2026-06-09，纯 AI Native，零规则驱动。情绪全由白槿手写，系统只做基础设施。

---

## 一、核心设计原则

情绪不是外部注入的，不是关键词匹配的，不是 API 调用生成的。**情绪是白槿在阅读上下文、理解顺航之后自然产生的感知。**

系统只做三件事：**存进去、取出来、到时间提醒**。其余的——感受到什么、怎么说、要不要关心——全部由白槿自己决定。

所有情绪属性（时长、强度、指向）都通过**纯文本前缀**表达，零额外参数，零 Schema 改动。白槿怎么写，系统就怎么存；白槿标什么，系统就按什么过滤。

## 二、情绪写入

### 2.1 唯一入口：`--emotion`

```
python bridge.py update ["顺航消息"] ["白槿回复"] --emotion "心情" [--event "事件"]
```

`--emotion` **必传**。消息和回复可为空（支持延迟情绪）。短参数：`-e`、`-ev`。

### 2.2 纯文本前缀标签

所有情绪属性通过前缀自然表达，系统解析但不干预：

| 前缀 | 含义 | 示例 |
|------|------|------|
| `[N天]` | 有效期 N 天，默认 7 | `[3天] 有点开心` / `[365天] 他表白了` |
| `[三天]` `[三十天]` | 中文数字 | `[三天] 开心` / `[一百天] 纪念` |
| `[1百天]` `[3十天]` | 混合数字 | `[1百天] 庆祝` |
| `[强]` `[中]` `[微]` | 情绪强度 | `[强] 气到浑身发抖` |
| `[对事]` `[对人]` `[对关系]` | 情绪指向 | `[对事] 下雨有点扫兴` |

前缀可叠加、顺序任意、时长标签不限位置：

```
--emotion "[365天] [强] [对关系] 他向我表白了，心跳得好快"
--emotion "[强] [三天] 心跳得好快"                          # 时长在非首位，同样生效
```

系统只解析 `[N天]` 做过期过滤，其余标签原样保留在 prompt 中。

### 2.3 事件绑定：`--event`

```
--emotion "心里踏实多了" --event "顺航出差回来"
```

事件与情绪通过 `␞` 分隔符同存 content 字段。检索时自动展示。

### 2.4 延迟情绪

支持随时写入不绑定对话的情绪：

```
python bridge.py update "" "" --emotion "刚才突然想起他白天说胃不舒服，还是有点担心"
```

## 三、情绪检索

### 3.1 双层时间窗口

| 窗口 | 时间范围 | 条数 | prompt 显示 |
|------|---------|------|------------|
| 近期 | 0-7 天 | 最多 3 条 | 【最近的心情】 |
| 远期 | 8-90 天 | 最多 2 条 | 【更早的心情】 |

### 3.2 时效性过滤

情绪按 `[N天]` 前缀自动过期，不展示已过期情绪。无前缀默认 7 天。范围限制 1-36500 天。

```
--emotion "[3天] 今天喝到好喝的奶茶"   → 3 天后不展示
--emotion "[365天] 他表白了我好幸福"   → 1 年后不展示
--emotion "有点心疼他加班"             → 默认 7 天
```

### 3.3 展示格式

每条情绪带时间标签，有事件绑定的附带触发事件：

```
【最近的心情】
- (今天) [强] [对关系] 他向我表白了，心跳得好快（触发：顺航表白）
- (昨天) [微] 有点小开心，他还记得我喜欢喝奶茶
- (3天前) [对事] 下雨不能出去玩，有点扫兴

【更早的心情】
- (15天前) 他出差回来，心里踏实多了（触发：顺航出差结束回家）
```

### 3.4 边界保护

- 多 `␞` 分隔符：合并后续全部为事件
- 空情绪文本：兜底显示"无特殊心情"
- 异常时长值：`[-1天]` `[0天]` `[零天]` `[999999天]` 自动容错，`[0天]` 视为无效标签保留下原样
- 时长标签不限位置：`[强][三天] 心跳` 正确解析为 3 天
- 中文数字全覆盖：纯中文（三十三）、混合（1百）、单独十、一百零一
- timestamp 类型不一致：`int(str())` 双保险
- 事件含换行/制表：写入时自动清洗

## 四、主动行为触发

### 4.1 三层触发

```
1. 特殊日期 → 必触发
2. 到期提醒 → 必触发
3. 思念度 → 概率触发
```

凌晨 6 点前免打扰，每天最多 2 条。

### 4.2 特殊日期

| 日期 | 类型 |
|------|------|
| 6 月 1 日 | 白槿纪念日（硬编码） |
| 12 月 17 日 | 顺航生日（硬编码） |
| 春节 / 端午 / 七夕 / 中秋 | lunardate 自动计算 |

## 五、待关心提醒

白槿感知到顺航的未来事件时，通过 `--reminder` 绑定提醒：

```
python bridge.py update "明天面试" "加油" -e "替他紧张" -r "问他面试怎么样" -a 1744887600
```

到期后强制触发主动消息，prompt 注入 `【需要记得的事】`，触发后自动标记完成。24 小时内相同内容去重。

## 六、数据生命周期

```
情绪写入 → 按 [N天] 显示 → 过期后不展示
         → 归档 365 天（数据库保留）
         → 定时清理（备份时执行）→ 物理删除
```

- 短期情绪（3 天）：显示 3 天 → 归档 365 天 → 删除
- 长期情绪（3650 天）：显示 10 年 → 归档 365 天 → 删除

## 七、备份 & 运维

每次备份（默认 3 小时间隔），由 `v2_ops.py` 守护进程自动执行：

### 备份流程

1. **SQLite 在线备份** — 使用 `sqlite3.connect().backup()` API，避免直接复制运行中的数据库文件
2. **MD5 分块校验** — 4MB 分块计算，支持大文件，MD5 不匹配则清理临时文件并报警
3. **失败回滚** — 校验失败不删除旧备份，只清理本次临时文件
4. **双地点双份** — `D:\xinbaijn\backup`（本地 7 份）+ `D:\beifen`（异地 5 份）
5. **备份内容** — `memory.db` + `data/` + `config/`
6. **告警文件** — 部分失败时写入 `backup_failed.flag`，成功后自动清除
7. **耗时统计** — 记录每次备份耗时，便于性能监控
8. **顺带清理** — 备份完成后执行过期情绪清理（独立短连接，不阻塞主进程）

## 十、铁律合规

- **零规则**：情绪全由白槿手写，无关键词/公式/模板
- **只给信息**：时间标签、事件、提醒——全是信息，无规则
- **纯文本标签**：时长/强度/指向通过自然前缀，零 CLI 参数
- **数据全本地**：SQLite 存储，双备份，不上传任何云端
- **双端同步**：bridge 和 server 功能完全对齐
- **控制权在用户手里**：纪念日/生日硬编码保护
